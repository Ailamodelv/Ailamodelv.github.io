# CPG 怎样连续切换步态：从相位差到可运行的四腿程序

读 CPG-RL 时，我最关心的一个问题是：**四条腿的相位差是固定写进去的，还是能够在运动中连续改变？具体每一步怎样算？**

在“推荐论文阅读”的学习对话里，这个问题经历了三次推进：先分清参数和耦合关系，再讨论行走与小跑的相位排列，最后追问“我要非常具体的实现方法流程”。这里把那条理解路线整理成一份可以回看的实现笔记。

本文先构造一个**人工指定目标相位的显式耦合模型**，把每一步计算看清楚，再与[CPG-RL 论文中的学习控制方式](/posts/cpg-rl-reading/)对照。程序只生成运动参考；没有接入机器人动力学、逆运动学或电机控制。相位表中的“四拍”和“对角同步”只描述时序，不能据此宣布已经实现稳定行走或小跑。

## 1. 两组变量：实际相位与目标偏置

把每条腿想成一个持续转动的时钟。固定腿的顺序为：左前 FL、右前 FR、左后 HL、右后 HR。

| 变量 | 程序里保存什么 | 是否每一步重新设定 |
| --- | --- | --- |
| $`\theta_i`$ | 第 $`i`$ 条腿现在走到了周期的哪个位置 | 初始化一次，之后积分累积 |
| $`\delta_i`$ | 希望这条腿相对于参考腿处于哪个位置 | 随目标步态改变 |
| $`\omega_i`$ | 实际相位的推进速度 | 根据当前误差计算 |
| $`\beta`$ | 一个参考周期中分配给支撑段的比例 | 与步态时序一起安排 |

这组教学用目标表把左前腿作为参考：

| 时序 | FL | FR | HL | HR |
| --- | --- | --- | --- | --- |
| 四拍起点 | 0° | 180° | 90° | 270° |
| 目标过渡到一半 | 0° | 180° | 135° | 315° |
| 对角同步终点 | 0° | 180° | 180° | 360° |

终点中，FL 与 HR 同相，FR 与 HL 同相，两组相差半个周期。360° 与 0° 在周期上等价；此处保留 360°，是为了表达 HR 从 270°继续前进的路径。

**FL 一列写 0°表示相对偏置为零，绝不表示左前腿停止转动。** 这张表不是所有机器人通用的步态标准，不同足序、相位原点和支撑比例会产生不同约定。

## 2. 改变相位差，靠的是一段时间内不同速

相位和相位速度之间的关系是：

```math
\dot\theta_i=\omega_i,
\qquad
\frac{d}{dt}(\theta_i-\theta_{\mathrm{FL}})
=\omega_i-\omega_{\mathrm{FL}}.
```

两条腿一直同速，原来的相位差便保持不变。若想让后腿多前进 90°，就要让速度差在一段时间内累积成 90°：

```math
\Delta(\theta_i-\theta_{\mathrm{FL}})
=\int_{t_0}^{t_1}(\omega_i-\omega_{\mathrm{FL}})\,dt.
```

例如前腿以 360°/s 推进，后腿暂时以 450°/s 推进 1 s，再恢复同速，后腿便相对多前进 90°。这是说明机制的手算；下面的程序会让前腿略减速、后腿略加速，共同完成调整。

这里还要分开“相位连续”和“速度连续”。直接改变速度而持续积分，可以保持相位连续，但速度会有阶跃。想使过渡更平顺，就需要让目标变化和调速过程也平顺。

## 3. 耦合项怎样决定加速还是减速

对第 $`i`$ 条腿，先比较每一条腿 $`j`$ 与它的实际相位差和目标相位差：

```math
e_{ij}=(\theta_j-\theta_i)-(\delta_j-\delta_i).
```

再计算：

```math
\omega_i=2\pi f+\frac{K}{4}\sum_{j=1}^{4}\sin(e_{ij}),
\qquad
\theta_i^{n+1}=\theta_i^n+\Delta t\,\omega_i^n.
```

本例取 $`f=1\ \mathrm{Hz}`$、$`K=10\ \mathrm{s^{-1}}`$、$`\Delta t=0.001\ \mathrm{s}`$。内部统一使用弧度，$`2\pi f`$ 的单位是 rad/s。

判断符号的方法很简单：当腿 $`j`$ 比预期更领先腿 $`i`$，且误差是一个小的正角度时，$`\sin(e_{ij})>0`$，这项就让腿 $`i`$ 加快，追赶相对位置。反向作用会让领先的一方减慢。$`j=i`$ 的一项恒为零；除以 4 是本例选用的平均耦合尺度。

当全部目标关系已满足，所有正弦项为零，四条腿便以相同基准速度推进。目标关系变化时，误差出现，速度开始调整。**程序改变的是相位的导数，没有把当前相位直接覆盖为新目标。**

这里的正弦是周期函数，不能把“小误差时会纠正”的直觉延伸成任意初值下都全局收敛。特别是恰好相差 $`\pi`$ 的某些排列，正弦误差也可能为零。本文只核验从给定四拍初值出发的连续过渡。

## 4. 把“什么时候切换”写成连续目标

在 2 s 前保持原目标，2—3 s 内切换，3 s 后保持新目标。令：

```math
u=\operatorname{clip}\left(\frac{t-2\ \mathrm{s}}{1\ \mathrm{s}},0,1\right),
\qquad b=3u^2-2u^3.
```

这个三次插值在起止点的一阶导数为零。目标偏置与支撑比例为：

```math
\boldsymbol\delta(t)=\frac{\pi}{180}
\begin{bmatrix}0&180&90+90b&270+90b\end{bmatrix}^{\!T},
\qquad \beta(t)=0.75-0.25b.
```

目标平滑变化，并不意味着实际值瞬间等于目标。有限耦合增益需要时间纠偏，因而会出现跟踪滞后。更大的 $`K`$ 一般会加快近目标处的响应，也会增加速度修正幅度、提高数值积分要求，不能无限增大。

另外，周期角度插值必须先决定沿哪个方向走。本例 HR 的目标使用 270°→360°，不能无意间写成 270°→0°并作普通线性插值，否则程序会要求它沿另一个方向走 270°。

## 5. 每个控制周期的核心代码

完整程序可从文末下载。下面保留控制循环最关键的部分，变量均按 FL、FR、HL、HR 排列：

```python
# 初始化只执行一次
theta = np.deg2rad([0.0, 180.0, 90.0, 270.0])

# 以下在每个 1 ms 控制周期执行
u = np.clip(t - 2.0, 0.0, 1.0)
blend = u * u * (3.0 - 2.0 * u)
delta = np.deg2rad([0, 180, 90 + 90*blend, 270 + 90*blend])

actual_diff = theta[None, :] - theta[:, None]
target_diff = delta[None, :] - delta[:, None]
error = actual_diff - target_diff
omega = 2*np.pi + 10.0*np.sin(error).mean(axis=1)

# 先用当前 theta 生成并记录 t 时刻的参考；再推进到 t + dt
theta = theta + 0.001 * omega
```

矩阵第 $`i`$ 行、第 $`j`$ 列都表示 $`j-i`$，两处顺序要一致。若只把其中一处写反，原本的纠偏可能变成把相位差推得更远。

`theta` 保留累积值。只有在计算周期位置时才取模；画相对相位曲线时保留连续角度，便于看清 360°附近的过渡。模运算后从接近 360°跳到 0°，有时只是表示方法的跳变，并不代表物理参考发生瞬移。

## 6. 相位如何变成足端参考

设归一化周期位置 $`p=(\theta\bmod 2\pi)/(2\pi)`$，范围为 $`[0,1)`$。本例约定周期前 $`1-\beta`$ 是摆动段，后 $`\beta`$ 是支撑段：

```math
q=\begin{cases}
p/(1-\beta),&p<1-\beta,\\
\bigl[p-(1-\beta)\bigr]/\beta,&p\geq1-\beta.
\end{cases}
```

$`q`$ 表示当前段已经走完的比例。取水平半幅 $`A=0.05\ \mathrm m`$、名义高度 $`H=0.25\ \mathrm m`$、抬脚高度 $`c=0.05\ \mathrm m`$，并令 $`B(q)=[1-\cos(\pi q)]/2`$：

```math
(x,z)=\begin{cases}
(-A+2AB(q),\,-H+c\sin^2(\pi q)),&\text{摆动段},\\
(A-2AB(q),\,-H),&\text{支撑段}.
\end{cases}
```

摆动段从后向前抬脚，支撑段从前向后回摆。两段在位置和段内一阶导数上衔接，周期绕回时的端点位置也一致。它是便于理解的运动学曲线，不代表地面接触求解器。

$`\beta`$ 在恒定相位速度下等于时间上的支撑占比；切换期间速度会变化，真实持续时间占比未必恰好等于瞬时 $`\beta`$。而机器人是否真的着地，还要看身体姿态、地形、执行器和接触动力学。

## 8. 这与 CPG-RL 论文有什么关系

共同的机制是：**速度经过积分成为相位，相位再进入运动参考生成器。** 决定速度的模块不同。

| 本文的教学实现 | CPG-RL 论文的做法 |
| --- | --- |
| 人工给定四拍与对角同步的目标表 | 没有使用本文这张目标表 |
| 根据相位误差显式计算速度修正 | 策略网络根据观测输出各腿的相位速度等调节量 |
| 目标差与当前差通过耦合项联系 | 文中去掉显式腿间振荡器耦合，协调通过策略形成 |
| 本文规定 2—3 s 完成目标切换 | 论文不因此提供同样的指定时间步态切换保证 |

论文中的策略以 100 Hz 输出，CPG 与底层控制以 1 kHz 运行。可以据此理解多速率循环：在两次网络决策之间继续积分，而不是等下一次决策才移动相位。实际复现还要按照论文定义处理幅度、轨迹朝向、动作缩放、观测和控制接口。[原论文](https://arxiv.org/abs/2211.00458)

“训练后的网络权重固定”和“控制参数不变”也是两回事。网络每次接收新的反馈，仍然可以输出不同的相位速度；这里不需要假定部署期间还在更新网络权重。

## 9. 这一轮追问留下的理解

我现在把“实现步态”拆成四个连续环节来记：**指定或学习节律关系 → 调整相位速度 → 积分得到相位 → 生成足端与关节参考。** 真实身体能否稳定跟随这些参考，是下一层需要验证的问题。

回看代码时，最值得核对的是：腿的排列是否一致；角度和角速度的单位是否一致；误差矩阵是否都采用同一差值方向；相位有没有被每步重置；切换时有没有正确处理周期角度的绕回。

这篇记录解决的是“相位差如何在程序里连续变化”。论文的完整控制链、观测与实验范围，放在[CPG-RL 论文精读](/posts/cpg-rl-reading/)；此前的[八神经元四足机器人笔记](/posts/eight-neuron-cpg-reading/)可以作为另一种节律控制结构的对照。
